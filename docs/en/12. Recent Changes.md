# Recent Changes (April 2026)

This document summarizes the most important recent changes in pyquotex for safer upgrades and troubleshooting.

## 1. Authentication fallback in connect()

### Problem fixed
When `session.json` had an expired token, the WebSocket could reject authorization and break long-running processes.

### Current behavior
- If there is no token: HTTP authentication runs with credentials.
- If a token exists: WebSocket connection is attempted with that token.
- If the token is rejected by WebSocket:
  - the in-memory session is cleared,
  - `authenticate()` is executed to refresh credentials,
  - WebSocket connection is retried with the new token.

### Benefit
Automatic recovery from invalid/expired session token without manual intervention.

## 2. Reliable get_candles() without network leak

### Problem fixed
In some broker scenarios, historical candles were not returned unless a minimal subscription trigger was sent first.

### Current behavior
- `get_candles()` triggers `subscribe_realtime_candle(asset, period)` to force history delivery.
- If `progressive=True`, realtime side channels are kept (`chart_notification` and `follow_candle`).
- If `progressive=False`, `unsubscribe_realtime_candle(asset)` always runs in `finally`.

### Benefit
Reliable historical snapshots and guaranteed subscription teardown in non-progressive mode.

## 3. Multi-asset concurrency safety

### Improvements
- Connection state is isolated per client instance.
- Realtime and candle structures are keyed by asset.
- Historical response routing uses correlation id where applicable.

### Benefit
Lower risk of cross-asset data contamination under concurrent workloads.
