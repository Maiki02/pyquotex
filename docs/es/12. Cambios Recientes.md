# Cambios Recientes (Abril 2026)

Este documento resume los cambios recientes más importantes de pyquotex para facilitar migraciones y troubleshooting.

## 1. Fallback de autenticación en connect()

### Problema resuelto
Cuando `session.json` tenía un token vencido, el flujo podía intentar conectar el WebSocket con ese token y fallar con rechazo de autorización, provocando corte del proceso.

### Comportamiento actual
- Si no hay token: se autentica por HTTP con credenciales.
- Si hay token: intenta conexión WebSocket.
- Si el token es rechazado por el WebSocket:
  - limpia la sesión en memoria,
  - ejecuta `authenticate()` para renovar token,
  - reintenta conexión WebSocket con el token nuevo.

### Beneficio
Recuperación automática ante token inválido sin intervención manual.

## 2. get_candles() confiable sin fuga de red

### Problema resuelto
En algunos escenarios, pedir histórico sin disparar suscripción mínima no devolvía datos y terminaba en timeout.

### Comportamiento actual
- `get_candles()` dispara `subscribe_realtime_candle(asset, period)` para forzar la entrega de datos históricos.
- Si `progressive=True`, mantiene canales de tiempo real (`chart_notification` y `follow_candle`).
- Si `progressive=False`, ejecuta `unsubscribe_realtime_candle(asset)` en `finally` para evitar fugas de ancho de banda.

### Beneficio
Histórico estable y cierre garantizado de suscripción en modo snapshot.

## 3. Seguridad de concurrencia multi-activo

### Mejoras aplicadas
- Estado de conexión aislado por instancia de cliente.
- Estructuras de velas y tiempo real indexadas por activo.
- Ruteo de respuestas históricas por correlation id cuando aplica.

### Beneficio
Menor riesgo de mezcla de datos entre activos/sesiones concurrentes.
