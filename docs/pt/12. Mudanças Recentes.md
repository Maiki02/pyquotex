# Mudanças Recentes (Abril 2026)

Este documento resume as mudanças recentes mais importantes do pyquotex para facilitar migração e troubleshooting.

## 1. Fallback de autenticação em connect()

### Problema resolvido
Quando o `session.json` continha token expirado, o WebSocket podia rejeitar a autorização e derrubar processos de longa execução.

### Comportamento atual
- Se não houver token: autenticação HTTP com credenciais.
- Se houver token: tenta conectar o WebSocket com esse token.
- Se o token for rejeitado:
  - limpa a sessão em memória,
  - executa `authenticate()` para renovar credenciais,
  - tenta novamente a conexão WebSocket com o novo token.

### Benefício
Recuperação automática de sessão inválida/expirada sem intervenção manual.

## 2. get_candles() confiável sem vazamento de rede

### Problema resolvido
Em alguns cenários do broker, o histórico não era retornado sem um trigger mínimo de assinatura.

### Comportamento atual
- `get_candles()` dispara `subscribe_realtime_candle(asset, period)` para forçar entrega do histórico.
- Se `progressive=True`, mantém canais de tempo real (`chart_notification` e `follow_candle`).
- Se `progressive=False`, executa `unsubscribe_realtime_candle(asset)` em `finally`.

### Benefício
Snapshot histórico confiável e teardown garantido da assinatura no modo não progressivo.

## 3. Segurança de concorrência multiativo

### Melhorias
- Estado de conexão isolado por instância de cliente.
- Estruturas de candles e tempo real indexadas por ativo.
- Roteamento de respostas históricas por correlation id quando aplicável.

### Benefício
Menor risco de contaminação cruzada entre ativos em cargas concorrentes.
